# WP-1.1-15: syrp-var: XmlElement, XmlDocument parsing, attribute access and serialisation

## Purpose
The XML DOM from master plan §5.2 (L2 Core, `syrp-var` lists `XmlElement`) and the XML half of Wave 1.1 item 2; WP-1.1-01 delivered the JSON half and left XML to a later WP in this crate. `syrp-state` persistence (WP-1.2-13), `PropertiesFile` (WP-1.2-06), the JUCE-compatible state formats (WP-1.2-08) and key files (WP-1.2-12) all build on it. Phase 1 exit criteria include a differential suite of XML edge cases, so every formatting rule the documentation leaves open is pinned and listed for the harness. Master plan §4.11 names `quick-xml` 0.42 (MIT) as the backend. Delivery: 3 PRs, each at most 1,200 changed lines (B1–B3 the element model, then B4–B5 the parser, then B6–B8 the writer and round trips).

## Behaviour
- B1. `XmlElement`: an owned tree node with a tag name, an ordered attribute list and an ordered list of children, where a child is an `XmlNode` that is either an element or a text node (JUCE's text elements, made with `XmlNode::text(..)`; `is_text_element`, `text`, `set_text`). `XmlElement::new(tag) -> Result<XmlElement, VarError>` rejects a name that `is_valid_xml_name` refuses (the XML 1.0 `Name` production; write the accepted set into the rustdoc), and `set_tag_name` does the same. No public fields (ADR 0003 D3). Unlike `Var`, `XmlElement` and `XmlNode` hold no `Rc` and are `Send + Sync`, so a document can be parsed on a worker thread; a compile-time test asserts it.
- B2. Attributes, as the `XmlElement` documentation describes them: `set_attribute(name, value)` with `&str`, `i32`, `i64`, `f64` and `bool` values (a replaced attribute keeps its position; a new one is appended), `has_attribute`, `string_attribute(name) -> Option<&str>` plus `string_attribute_or(name, default)`, `int_attribute(name, default)`, `double_attribute(name, default)`, `bool_attribute(name, default)`, `compare_attribute(name, value, ignore_case)`, `remove_attribute`, `remove_all_attributes`, `num_attributes`, `attribute_name(i)`, `attribute_value(i)` and an iterator of `(name, value)` pairs (`XmlAttribute`). Names are case-sensitive. Text-to-number and text-to-bool conversion reuse the `Var` conversion table of WP-1.1-01 B3, so both crates agree; a test checks a shared vector table against both. Names may be passed as `&str` or `Identifier`. `f64` values are written in the shortest form that reads back to the same value.
- B3. Children and text: `add_child_element`, `prepend_child_element`, `insert_child_element(node, index)` (an index past the end appends, as documented), `create_new_child_element(tag) -> Result<&mut XmlElement, VarError>`, `add_text_element`, `remove_child(index) -> Option<XmlNode>`, `delete_all_child_elements`, `delete_all_child_elements_with_tag_name`, `num_children`, `child(index)`, `child_elements()` (an iterator that skips text nodes), `child_by_name(tag)`, `child_by_attribute(name, value)`, `contains_child`, `has_tag_name` and `has_tag_name_ignoring_namespace`, `namespace` and `tag_name_without_namespace`, `all_sub_text()` (all descendant text in document order), `child_element_all_sub_text(tag, default)`, `replace_child_element(index, node)`, `sort_child_elements(compare)` (stable) and `is_equivalent_to(other, ignore_order_of_attributes)` (same tag, attributes and children in order; text compared exactly).
- B4. `XmlDocument`: `XmlDocument::parse(&str) -> Result<XmlElement, VarError>` and a builder `XmlDocument::new(text)` with `ignore_empty_text_elements` (default on, as the `XmlDocument` documentation gives it: whitespace-only text between elements is dropped) and `only_read_outer_element`; `parse_bytes(&[u8])` detects a UTF-8 or UTF-16 byte-order mark and honours an `encoding` declaration of UTF-8 or UTF-16 (any other encoding is a coded error). The parser accepts the XML declaration, comments and processing instructions (dropped), CDATA sections (kept as text), the five predefined entities and decimal and hexadecimal character references. A `DOCTYPE` is skipped: no entity it declares is expanded and nothing outside the text is ever fetched, so there is no external-entity or entity-expansion attack (tested with a billion-laughs document and an external `SYSTEM` entity, both rejected or ignored with no allocation blow-up). A document without exactly one root element, mismatched or unclosed tags, an undefined entity, a duplicate attribute or an invalid name is a coded error carrying line and column.
- B5. Robustness: parse, clone, drop, `is_equivalent_to` and the writer are iterative, never recursive, so a 100,000-level nested document neither overflows the stack nor needs a depth limit; tests cover each operation at that depth. A proptest feeds random bytes and mutated valid documents to the parser and asserts error-or-success without a panic.
- B6. Writer: `to_string(&TextFormat) -> String` and `write_to(&mut impl std::io::Write, &TextFormat) -> std::io::Result<()>`, where `TextFormat` follows the `XmlElement::TextFormat` documentation: `dtd`, `custom_header`, `add_default_header` (the header line written when no custom one is given), `line_wrap`, `new_line_chars`, `indentation` (per level, in spaces), `single_line()` and `without_header()`. Escaping: `&`, `<`, `>` and `"` in attribute values, `&`, `<` and `>` in text, and control characters as numeric references; other characters are written as UTF-8. Empty elements are written in the short form. Where the documentation does not fix a detail (the header text, line-wrap points, `'` and `>` escaping, whether a text-only element stays on one line), choose it, pin it with a `b6_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md` for the differential harness (WP-0.1-11).
- B7. Round trip: a proptest builds random trees (valid names, attribute values and text with every escapable character, CDATA-like and non-ASCII text, empty and whitespace-only text) and checks `parse(to_string(t))` `is_equivalent_to` `t` after the documented normalisation (adjacent text nodes merge; whitespace-only text is dropped when `ignore_empty_text_elements` is on), for the default, single-line and no-header formats.
- B8. Errors continue `errors/var.toml` from the next free code (`SYRP-VAR-0004` today): invalid XML name, malformed XML with line and column, unsupported encoding, more than one or no root element. A `docs/migration/` page maps `XmlElement`, `XmlDocument`, `parseXML`, `parseXMLIfTagMatches` and `XmlElement::TextFormat` to this API, and records that JUCE's `getNextElement` sibling links become iteration over `children()`.

## Not in this WP
Reading XML from a `File`, URL or `InputStream` (`parseXML(File)`, `readEntireXmlStream`) and `writeTo(File)` (they need `syrp-io`; callers read the text first), external entities and `XmlDocument::setInputSource`, namespaces beyond the prefix helpers in B3, DTD validation, and any mapping between `Var` or `ValueTree` and XML (WP-1.2-13, WP-1.2-08).

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.1-15` first and `cargo syrp wp check WP-1.1-15` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
