# WP-1.2-06: syrp-state: PropertySet, PropertiesFile and ApplicationProperties

## Purpose
Wave 1.2 item 6: application settings files from master plan §5.9 ("`PropertiesFile` and `ApplicationProperties` use platform-appropriate locations"), with `PropertySet` from `juce_core`, which they are built on. It uses `File`, special locations and `TemporaryFile` (WP-1.1-04), the gzip streams (WP-1.1-05), `XmlElement` (WP-1.1-15, through WP-1.2-13), and `Broadcaster<()>` and the loop's timers (WP-1.2-01) for change messages and delayed saving. It works in the crate WP-1.2-03 creates, after WP-1.2-07. The file layouts here are Syrp's own; reading files that JUCE wrote is WP-1.2-08. Delivery: 2 PRs, each at most 1,200 changed lines (B1–B3, then B4–B6).

## Behaviour
- B1. `PropertySet`: string keys to string values in insertion order, as the `PropertySet` documentation describes, with an `ignore_case_of_key_names` option. `value(key) -> Option<String>`, `value_or(key, default)`, `int_value`, `double_value` and `bool_value` with defaults (text conversion follows the `Var` table of WP-1.1-01 B3), `xml_value(key) -> Option<XmlElement>`, `set_value(key, v)` for `&str`, `i32`, `i64`, `f64`, `bool` and `&XmlElement` (stored as single-line XML text), `remove_value`, `contains_key`, `clear`, `all_properties()`, a fallback set consulted for missing keys (`set_fallback`), and `create_xml(tag)`/`restore_from_xml(&XmlElement)`. It is `Send + Sync` and internally locked, as the documentation says it is thread-safe; a change callback (JUCE's `propertyChanged`) runs after the lock is released.
- B2. `PropertiesFile::Options`: `application_name`, `filename_suffix`, `folder_name`, `osx_library_sub_folder`, `common_to_all_users`, `ignore_case_of_key_names`, `do_not_save`, `milliseconds_before_saving`, `storage_format` (`Xml`, `Binary`, `CompressedBinary`) and `process_lock`, plus `default_file() -> Result<File, StateError>`, which follows the per-platform rules the `PropertiesFile::Options` documentation gives for Linux, macOS (`~/Library/<osx_library_sub_folder>`) and Windows (application data). Write the table into the rustdoc; where the documentation is silent, choose (on Linux, prefer the XDG config directory) and pin it with a `b2_..._syrp_choice` test. Tests point the options at a temporary base directory.
- B3. Load and save: `PropertiesFile::new(options)` (or `with_file(file, options)`) loads the file; a missing file is an empty set, and an unreadable or corrupt one is an empty set with `is_valid_file() == false`, as documented. `save() -> Result` writes the whole set atomically through `TemporaryFile`, in the chosen format: `Xml` (a documented Syrp layout of the B1 `create_xml` form), `Binary` (a documented length-prefixed layout over the `syrp-io` streams) or `CompressedBinary` (the same, gzip-wrapped). `do_not_save` makes `save` succeed without writing. With `process_lock`, load and save hold an exclusive lock on a sibling `<file>.lock` through `std::fs::File::lock` (stable since Rust 1.89), so two processes never interleave writes; tested with two child processes.
- B4. Change handling: every change marks the file as needing a save and sends on a `Broadcaster<()>` (`change_broadcaster()`). With `milliseconds_before_saving > 0`, a save is scheduled that long after the last change through the message loop (changes in between coalesce), `0` saves at once, and a negative value never saves automatically. `needs_to_be_saved`, `set_needs_to_be_saved`, `save_if_needed`, `reload` and `file()`. Dropping a `PropertiesFile` saves if needed, as the documentation describes, and ignores a failure (documented; prefer `save_if_needed` in examples). Timing tests use `ManualLoop`.
- B5. `ApplicationProperties`: `set_storage_parameters(options)`, `user_settings()`, `common_settings(return_user_if_not_writable)` (the all-users file, or the user file when that is not writable and the flag is set, as documented), `save_if_needed()` and `close_files()`.
- B6. Tests: a proptest round trip of random sets through all three formats; corrupt and truncated files; key-case handling; fallback lookups; and saving from several threads at once. Errors continue `errors/state.toml`.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.2-06` first and `cargo syrp wp check WP-1.2-06` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
