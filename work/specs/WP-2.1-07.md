# WP-2.1-07: syrp-midi-utils: MidiMessageSequence, MidiKeyboardState, RPN detector and generator, and MIDI message helpers

## Purpose
Wave 2.1 item 7. `MidiMessage` and `MidiBuffer` are already in the frozen `syrp-midi` contract (WP-0.2-03), which a WP cannot extend, so this WP creates a new L3 crate, `syrp-midi-utils`, for the rest of `juce_audio_basics`' MIDI classes: `MidiMessageSequence`, `MidiKeyboardState`, the RPN classes and the message helpers the contract's `AGENTS.md` lists as gaps (named meta events, float velocity, note names). `MidiFile` (WP-2.1-08) and UMP translation (WP-2.1-09) live in modules of this crate and run in parallel once it merges; `syrp-mpe` (WP-2.1-06) uses the RPN detector. Delivery: 3 PRs, each at most 1,200 changed lines (B1–B2, then B3, then B4–B6).

## Behaviour
- B1. Helpers (`message` module), free functions over `syrp_midi::MidiMessage` and `MidiData`: `tempo_meta_event(microseconds_per_quarter)`, `time_signature_meta_event(numerator, denominator)`, `key_signature_meta_event(sharps_or_flats, is_minor)`, `text_meta_event(kind, &str)`, `end_of_track()`, `midi_channel_meta_event(channel)` and readers for each (`tempo_seconds_per_quarter_note`, `time_signature`, `key_signature`, `text`); `note_on_float(channel, note, velocity: f32)` and `float_velocity` (the velocity scaling the `MidiMessage` documentation describes); `note_name(note, use_sharps, include_octave, middle_c_octave)` and `note_frequency(note, a4_hz)`; `controller_name(n)` and the General MIDI instrument and drum names the documentation lists; `all_notes_off`, `all_sound_off` and `all_controllers_off` for a channel.
- B2. `MidiMessageSequence`: an ordered list of `MidiEventHolder`s (a message with a timestamp and an optional index of its matching note-off), `add_event(message, time_adjustment)`, `delete_event(index, delete_matching_note_up)`, `add_sequence(&other, time_adjustment)` and the time-ranged form, `update_matched_pairs()`, `index_of_matching_key_up`, `time_of_matching_key_up`, `next_index_at_time`, `start_time`, `end_time`, `event_time`, `sort()` (stable by time), `extract_midi_channel_messages`, `extract_sys_ex_messages`, `delete_midi_channel_messages`, `delete_sys_ex_messages` and `create_controller_updates_for_time(channel, time) -> Vec<MidiMessage>`, as the `MidiMessageSequence` documentation describes them. Matching pairs are indices kept correct by every edit, never pointers.
- B3. `MidiKeyboardState`: 16 channels × 128 notes, `note_on`, `note_off`, `all_notes_off(channel or all)`, `is_note_on`, `is_note_on_for_channels(mask, note)`, `process_next_midi_event` and `process_next_midi_buffer(buffer, start, frames, inject_indirect_events)`, as documented. Listener callbacks (`handle_note_on`, `handle_note_off`) run on the thread that changed the state, as JUCE's do. The state is `Send + Sync` through atomics, so a UI thread can read it while the audio thread updates it without a lock; notes pressed from the UI are queued through a `syrp_rt` SPSC queue and injected by the next `process_next_midi_buffer` call, which never allocates (`syrp_rt::no_alloc` test).
- B4. RPN: `MidiRpnMessage` (channel, parameter number, value, is-NRPN, is-14-bit), `MidiRpnDetector::try_parse(channel, controller, value) -> Option<MidiRpnMessage>` and `reset()`, following the controller sequences (CC 101/100, 99/98, 6/38, and the null RPN) the `MidiRPNDetector` documentation and the MIDI 1.0 specification describe, and `MidiRpnGenerator::generate(..) -> [MidiMessage; 4]`. Proptest: generated messages parse back to the same RPN.
- B5. Crate layout for the parallel WPs: `src/lib.rs` declares `pub mod file;` and `pub mod ump;` with stub modules, `tests/file.rs` and `tests/ump.rs` stubs, a `benches/ump.rs` stub registered as a `harness = false` bench, and `proptest` and `syrp-rt` (with `GuardedAllocator`) as dev-dependencies, so WP-2.1-08 and WP-2.1-09 never need to edit `Cargo.toml` or `lib.rs`. The crate `AGENTS.md` names those owners in a module table, as `syrp-audio-basics` does.
- B6. Errors continue `errors/midi.toml` (`SYRP-MIDI-0005` onwards). Dependencies: `syrp-midi`, `syrp-error` and `syrp-rt` only.

## Not in this WP
`MidiFile` (WP-2.1-08), MIDI 2.0 translation and dispatch (WP-2.1-09), `MidiMessageCollector` and MIDI devices (`syrp-midi-io`), `MidiBuffer` merging (a contract change), and `MidiKeyboardComponent`.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-07` first and `cargo syrp wp check WP-2.1-07` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
