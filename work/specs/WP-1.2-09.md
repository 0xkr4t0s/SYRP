# WP-1.2-09: syrp-crypto: MD5, SHA256, Whirlpool, BlowFish, Primes and raw RSAKey

## Purpose
Wave 1.2 item 9: `juce_cryptography` from master plan §4.13 and §5.2 (L2 Headless extras). Master plan §4.13 decides the stack: RustCrypto `md-5`, `sha2`, `blowfish` and `whirlpool` for hashes and the cipher, and big-number arithmetic for JUCE-style raw RSA, never the `rsa` crate (RUSTSEC-2023-0071, unpatched). Key files (WP-1.2-12) use the RSA and hash parts. Hashing files and streams uses `syrp-io` (WP-1.1-04) and prime generation and RSA use `syrp-maths`' `Random` (WP-1.1-11) and `BigInteger` (WP-1.1-16). This WP creates `syrp-crypto`. Delivery: 2 PRs, each at most 1,200 changed lines (B1–B2, then B3–B6).

## Behaviour
- B1. Hashes: `Md5`, `Sha256` and `Whirlpool`, each a small value type with `from_bytes(&[u8])`, `from_utf8(&str)` (the bytes of the UTF-8 text, as JUCE's `CharPointer_UTF8` constructors document), `from_input_stream(&mut dyn InputStream, max_bytes: Option<u64>) -> Result<Self, CryptoError>`, `from_file(&File) -> Result<Self, CryptoError>`, `raw_data()` (a fixed-size byte array), `to_hex_string()` (lower case), `Eq`, `Hash` and `Display`. Built on `md-5` 0.11, `sha2` 0.11 and `whirlpool` 0.11 with default features off except what pure-Rust hashing needs. Tests: the RFC 1321 MD5 suite, the FIPS 180-4 example vectors for SHA-256, the published ISO/NESSIE Whirlpool vectors, and a proptest that streaming in random chunk sizes equals one-shot hashing.
- B2. `BlowFish`: `BlowFish::new(key: &[u8]) -> Result<BlowFish, CryptoError>` accepting the key lengths the `BlowFish` documentation accepts (others are a coded error), `encrypt_block(&mut u32, &mut u32)` and `decrypt_block`, and the buffer forms `encrypt(&mut Vec<u8>)` and `decrypt(&mut Vec<u8>) -> Result<(), CryptoError>` with the padding the class documentation describes. If the documentation does not fix the padding, choose PKCS#7, pin it with a `b2_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md` for the differential harness. Built on `blowfish` 0.10. Tests: the published Blowfish ECB test vectors (Eric Young's set), a buffer round-trip proptest, and wrong-padding errors.
- B3. Big numbers: RSA and primes use `syrp_maths::BigInteger` (WP-1.1-16) for every number in the public API and do their arithmetic through it (`exponent_modulo`, `inverse_modulo`, `find_greatest_common_divisor`). No `num-bigint` type, nor any other third-party big-number type, appears in this crate's public API, and the crate does not depend on `num-bigint` directly.
- B4. `Primes`: `create_probable_prime(bit_length, certainty, random_seeds: &[i32]) -> BigInteger` and `is_probably_prime(&BigInteger, certainty) -> bool` (Miller–Rabin, `certainty` rounds), deterministic for given seeds through `syrp_maths::Random`. Tests: small primes and composites, Carmichael numbers, and primes from a published table.
- B5. `RsaKey`: `RsaKey::from_string(&str) -> Result<RsaKey, CryptoError>` and `to_string()` in the textual form the `RSAKey` documentation describes, `is_valid`, `apply_to_value(&mut BigInteger)`, and `create_key_pair(num_bits, random_seeds) -> (RsaKey, RsaKey)`. This is raw (textbook) RSA with no padding, as JUCE's class is: the rustdoc says in its first paragraph that it is for key files and compatibility only and not for network-facing use, and recommends `ed25519-dalek` for new licensing schemes (§4.13). Tests: public-then-private and private-then-public restore random values below the modulus; key strings round-trip; seeded generation is deterministic; an invalid key string is a coded error.
- B6. Errors use the new `errors/crypto.toml` domain (`SYRP-CRYPTO-0001`...); `CryptoError` implements `Diagnostic`. No `unsafe`, no C or assembly code, no `rsa`, `ring` or `aws-lc-rs` dependency.

## Not in this WP
Constant-time guarantees for the RSA and BlowFish parts (they are compatibility primitives), modern ciphers, and TLS (rustls lives in `syrp-net`). `BigInteger` itself is WP-1.1-16.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.2-09` first and `cargo syrp wp check WP-1.2-09` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
