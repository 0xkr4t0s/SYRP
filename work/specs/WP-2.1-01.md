# WP-2.1-01: syrp-audio-basics: crate skeleton, AudioBuffer and vector operations

## Purpose
Creates `syrp-audio-basics` (master plan §5.2, L3 Audio; Wave 2.1 item 1, brought forward because it needs only merged contracts) with the owned audio buffer and the vector operations. It also lays out the module skeleton so that WP-2.1-03 (control-rate DSP) and WP-2.1-05 (`VoicePool`) can work in parallel in their own directories once this merges. Storage follows ADR 0003 D2 (one allocation per buffer, 64-byte channel alignment, stride a multiple of 64 bytes) and its views are the `syrp-audio-api` types. Delivery: 2–3 PRs (B1–B2, then B3–B4, then B5–B6).

## Behaviour
- B1. Skeleton: `src/lib.rs` declares `pub mod buffer; pub mod vector_ops; pub mod control; pub mod voice;`. `src/control/mod.rs` and `src/voice/mod.rs` hold only a module doc comment naming their owners (WP-2.1-03 and WP-2.1-05). `Cargo.toml` depends on `syrp-audio-api`, `syrp-rt`, `syrp-simd` and `syrp-error`, has `proptest` as a dev-dependency, and declares three Callgrind benches with `harness = false`: `buffer`, `control` and `voice_pool`; create `benches/control.rs` and `benches/voice_pool.rs` as stubs whose `main` prints that the owning WP has not landed. `AGENTS.md` maps each module and bench to its WP. Do not create `tests/control.rs` or `tests/voice_pool.rs`.
- B2. `AudioBuffer<T: AudioSample>`: an owned buffer in one `syrp_simd::AlignedBuf` allocation, each channel starting on a 64-byte boundary, with `new(channels, frames)` (zeroed), `channels`, `frames`, `as_block() -> AudioBlock<T>`, `as_block_mut() -> AudioBlockMut<T>`, `channel`, `channel_mut`. `set_size(channels, frames, keep_existing, clear_extra, avoid_reallocating)` follows the `AudioBuffer::setSize` documentation; with `avoid_reallocating` and enough capacity it never allocates (test under `syrp_rt::no_alloc`). `make_copy_of(&AudioBuffer<U>)` converts between `f32` and `f64`. No public fields (ADR 0003 D3).
- B3. Cleared flag: the buffer tracks whether it is known to be silent, as `hasBeenCleared` is documented: `clear` sets it, any mutable access clears it, operations that add or copy from a cleared source keep the destination's state where the documentation says so, and `is_clear()` reports it. Operations skip work on a cleared buffer where the result is unchanged.
- B4. Buffer operations, all allocation-free: `clear` (all, one channel, a frame range), `apply_gain` and `apply_gain_ramp` (linear from start gain to end gain over the range), `add_from` and `copy_from` (with gain), `add_from_with_ramp` and `copy_from_with_ramp`, `magnitude` (peak) and `rms_level` per channel and range, `find_min_max`, `reverse`. Results agree with a plain scalar loop at the `f32-arith` tolerance (master plan §9.3).
- B5. `vector_ops`: the `FloatVectorOperations` set over slices of `f32` and `f64`, built on `syrp_simd::kernels` where a kernel exists and written once against `Sample` with `syrp_simd::dispatch` where it does not: `clear`, `fill`, `copy`, `copy_with_multiply`, `add` (scalar and slice), `subtract`, `multiply` (scalar and slice), `negate`, `abs`, `min`/`max` (with a scalar and between slices), `clip`, `find_minimum`, `find_maximum`, `find_min_max`, `convert_fixed_to_float` (`i32` to `f32` with a multiplier). Each has a scalar reference; a proptest checks every dispatch level against it on unaligned lengths and offsets (`f32-arith` tolerance).
- B6. ADR 0003 D7: a proptest applies random `set_size`, write and clear sequences and checks the alignment and stride invariants and that kept content survives; a Callgrind bench (`benches/buffer.rs`, same harness style as `crates/foundation/simd/benches/instructions.rs`) counts instructions for `apply_gain`, `add_from` and `rms_level` on a 2 × 512 buffer. Every public operation is `RtSafe` and tested under `syrp_rt::no_alloc`.

## Not in this WP
`AudioSourceChannelInfo` and the source family, data converters (`AudioData`), `AudioWorkgroup`. Stereo lane filling for voices belongs to WP-2.1-05.

## Crate setup
Create `crates/audio/audio-basics/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-01` first and `cargo syrp wp check WP-2.1-01` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
