# WP-1.1-06: syrp-thread: Thread, priorities and realtime threads, WaitableEvent, ThreadPool and SpinLock

## Purpose
The threading layer from master plan §5.2 (L2 Core), §5.4 (background workers) and Wave 1.1 item 6. `syrp-process`, `syrp-net`, the device backends and the plugin scanner run on these threads, and audio backends ask them for realtime priority. JUCE's lock classes map to `std` types instead of being rewritten (B5). Delivery: 3 PRs (B1–B2, then B3 and B5, then B4 and B6).

## Behaviour
- B1. `Thread`: `Thread::builder(name).priority(Priority).stack_size(n).realtime(RealtimeOptions).spawn(f)`, where `f: FnOnce(&ThreadContext) + Send + 'static`, returns a `ThreadHandle` with `signal_thread_should_exit()`, `notify()`, `is_running()`, `id()` and `stop(timeout) -> Result<Stopped, ThreadError>`. Inside, `ctx.thread_should_exit()` and `ctx.wait(timeout) -> bool` (woken by `notify` or by the exit signal). Free functions: `current_thread_id()`, `current_thread_name()`, `sleep(Duration)`, `yield_now()`, and `Thread::launch(f)` for a fire-and-forget thread. Rust cannot kill a thread, so `stop` signals, waits, and on timeout returns `SYRP-THREAD-0001` and leaves the thread detached; this documented deviation replaces JUCE's forced kill. Dropping a handle signals exit and joins.
- B2. Priorities: `Priority::{Lowest, Low, Normal, High, Highest}` and `RealtimeOptions` (priority 0–10, optional processing period and expected work time, as the `Thread::RealtimeOptions` documentation lists). Write the per-platform mapping into the rustdoc: Linux uses nice values, and `SCHED_FIFO` or `SCHED_RR` for realtime; macOS uses QoS classes, and the Mach time-constraint policy for realtime; Windows uses `SetThreadPriority`, and MMCSS "Pro Audio" (`AvSetMmThreadCharacteristicsW`) for realtime. When the OS refuses (no `RLIMIT_RTPRIO` on a CI runner, for example), the thread still runs at normal priority and `spawn` reports the refusal through `ThreadHandle::realtime_status()` instead of failing. `set_current_thread_priority` and `set_current_thread_affinity_mask(u64)`; affinity is unsupported on macOS and returns a coded error there.
- B3. `WaitableEvent::new(manual_reset)`: `wait(timeout: Option<Duration>) -> bool`, `signal()` and `reset()`. Auto-reset wakes exactly one waiter and clears itself; manual-reset stays signalled until `reset`. A signal before any wait is not lost. Test with `std` threads for timeouts, and with a loom model (`--cfg loom`, `loom` as a dev-dependency) of signal, wait and reset interleavings.
- B4. `ThreadPool::new(ThreadPoolOptions { thread_name, num_threads (default: logical CPUs from `syrp-sys`), stack_size, priority })`. Jobs are a `ThreadPoolJob` trait (`name`, `run_job(&mut self, &JobContext) -> JobStatus::{Finished, RunAgain}`) or closures. `add_job` returns a `JobHandle`; `remove_job(handle, interrupt, timeout)`, `remove_all_jobs(interrupt, timeout, filter)`, `num_jobs`, `num_threads`, `contains`, `is_job_running`, `wait_for_job_to_finish(handle, timeout)` and `move_job_to_front`. `JobContext::should_exit()` turns true when a job is interrupted. Jobs start in FIFO order; a `RunAgain` job goes to the back of the queue; a job never runs on two threads at once. Dropping the pool interrupts every job and waits for the running ones. Tests: every job runs exactly once; interruption is seen; `RunAgain` counts; removing a running job with a timeout reports the timeout.
- B5. Locks, mapped instead of copied: `CriticalSection` and `ScopedLock` map to `std::sync::Mutex` (JUCE's is re-entrant and `std`'s is not; the mapping note says how to restructure), `ReadWriteLock` to `std::sync::RwLock`, and `ThreadLocalValue` to `thread_local!`. Write these into a page under `docs/migration/` for the migration map. `SpinLock` is provided: `lock()` spins with backoff and then yields, `try_lock()` makes no system call, and the guard is RAII. Loom model for `SpinLock` mutual exclusion.
- B6. Errors use the new `errors/thread.toml` domain (`SYRP-THREAD-0001`...). Dependencies: `syrp-rt`, `syrp-sys`, `libc`, `windows-sys` and `loom` (dev, `cfg(loom)`); list new ones in `deps_added`. Every platform call has a `// SAFETY:` comment.

## Platforms
Linux, macOS and Windows are required, and CI must pass on all three. Realtime and affinity tests accept "granted" or the documented refusal on CI runners; nightly device-lab runners (§9.6) may assert that the grant succeeds. iOS and Android use the Linux and macOS paths where they apply and are not tested in this WP.

## Not in this WP
`HighResolutionTimer` and `TimeSliceThread` (WP-1.1-07), audio workgroups (`syrp-audio-basics`), `InterProcessLock` (WP-1.1-08).

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.1-06` first and `cargo syrp wp check WP-1.1-06` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
