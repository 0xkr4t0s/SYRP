# WP-2.1-14: syrp-format-wav: WAV, WAVE_FORMAT_EXTENSIBLE, RF64 and WAV metadata chunks

## Purpose
Wave 2.1 item 14 (the WAV half; AIFF is WP-2.1-17): `syrp-format-wav`, an `AudioFormat` implementation of the frozen `syrp-format-api` contract (WP-0.2-04) for RIFF WAVE, `WAVE_FORMAT_EXTENSIBLE`, RF64/BW64 and the metadata chunks JUCE's `WavAudioFormat` documentation names. Master plan §4.2 decides to build WAV rather than wrap `hound`, because metadata parity (BWF, cue, smpl, acid, iXML) must be Syrp's own, and §9.3 puts integer PCM decoding in the `exact` profile. The layout comes from public sources only: Microsoft's RIFF and `WAVEFORMATEXTENSIBLE` documentation, EBU Tech 3285 (BWF `bext`), EBU Tech 3306 (RF64) and ITU-R BS.2088 (BW64). This WP creates `syrp-format-wav`. Delivery: 3 PRs, each at most 1,200 changed lines (B1–B2, then B3–B4, then B5–B6).

## Behaviour
- B1. `WavAudioFormat` implements `AudioFormat`: `name()` and `file_extensions()` (`.wav`, `.bwf`) as the `WavAudioFormat` documentation lists them, `sample_rates()` and `bit_depths()` for writing (8, 16, 24 and 32 integer, and 32-bit float), `can_read(header)` true for `RIFF`, `RF64` and `BW64` containers whose form type is `WAVE`. `create_reader` and `create_writer` return `Box<dyn AudioReader>` / `Box<dyn AudioWriter>`. `WavAudioFormat::with_rf64_threshold(bytes)` lowers the size at which the writer switches to RF64 (for tests and for callers who want RF64 always); the default is the 4 GiB limit of a 32-bit RIFF size.
- B2. Reading: walk the chunk list (honouring the pad byte after odd-sized chunks, skipping unknown chunks) and read format tag 1 (PCM: 8-bit unsigned, 16, 24 and 32-bit signed little-endian), 3 (IEEE float, 32 and 64-bit) and `0xFFFE` (extensible, with the PCM and float sub-format GUIDs; `valid_bits_per_sample` narrower than the container is honoured), and RF64/BW64 sizes from the `ds64` chunk. The channel mask maps to a `ChannelSet` through a private table of Microsoft's published speaker bits (a mask the contract's speakers cannot express, or none, gives a discrete layout). `read_samples` converts to `f32`/`f64` by dividing by 2^(bits − 1) (8-bit is offset by 128 first), the mapping WP-2.1-02 B2 states (implemented locally: format crates do not depend on `syrp-audio-basics`). Every size and count is checked against the remaining input before allocating; malformed input is a coded error continuing `errors/format.toml` (`SYRP-FORMAT-0006` onwards), never a panic. Where the public specifications leave a case open (a `data` size of 0 or `0xFFFFFFFF` in a streamed file, a `data` chunk that runs past the end, a missing `fmt `), choose, pin it with a `b2_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md` for the harness.
- B3. Metadata reading, into the contract's `Metadata` in file order: `bext` → `Bext` (time reference, description, originator, originator reference, date, time, coding history); `cue ` plus `LIST`/`adtl` `labl` and `note` → `CuePoint`s with labels; `smpl` loops → `SampleLoop` (forward, ping-pong and backward; other loop types become `Other`); `LIST`/`INFO` text → `Tag`s (`INAM` Title, `IART` Artist, `IPRD` Album, `IGNR` Genre, `ICRD` Date, `ICMT` Comment, `ITRK` TrackNumber, `ICOP` Copyright, `ISFT` Encoder; other INFO ids → `Tag::Custom`); every other chunk JUCE's documentation names (`acid`, `inst`, `iXML`, `axml`, `Trkn`, `cart`) → `MetadataItem::Other(chunk_id, bytes)` unchanged. Text fields drop trailing NULs and are read as UTF-8, falling back to Latin-1 (Syrp's choice, pinned and listed).
- B4. Writing: integer PCM at 8, 16, 24 and 32 bits and 32-bit float; float-to-integer conversion follows the rounding, clipping and NaN rule WP-2.1-02 B2 states. The header uses `WAVE_FORMAT_EXTENSIBLE` with a channel mask when there are more than two channels or more than 16 bits, as Microsoft's guidance says, and the plain format otherwise. The writer reserves a `JUNK` chunk the size of a `ds64` chunk and, if the data passes the RF64 threshold, rewrites the header as RF64 in `finish`, as EBU Tech 3306 describes; otherwise it patches the RIFF and `data` sizes. Metadata items are written in their order, `Other` items byte for byte, after `fmt ` and before `data` (Syrp's choice, documented).
- B5. Tests: every format and bit depth round-trips `f32 → file → f32` exactly for values on its grid; every metadata item round-trips; files with odd chunks, unknown chunks, extensible headers, `valid_bits_per_sample` < container size and RF64 (through `with_rf64_threshold`) read correctly; a byte-flip and truncation proptest over valid files never panics and never allocates more than the input justifies. Test files are built by the tests from the public layouts, never copied from elsewhere.
- B6. Add scenario files under `parity/scenarios/formats/wav/` (the WP-0.1-11 format) in which JUCE reads the B5 files (including malformed ones) and writes each format with metadata; scenario files hold inputs only, and expected outputs come solely from harness runs. The crate `AGENTS.md` lists the ledger rows, the mapping from JUCE's documented metadata keys to the contract's items (for WP-1.9's compat layer), and each `syrp_choice`.

## Not in this WP
The format manager and reader sources (`syrp-formats`), memory-mapped readers, Sony Wave64, ADPCM and other compressed WAV codecs, and the `bext` UMID and loudness fields (a contract gap; they travel as `Other` until the contract grows).

## Crate setup
Create `crates/audio/format-wav/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed. Dependencies: `syrp-format-api`, `syrp-audio-api` and `syrp-error` (streams are the contract's `std::io` `ReadSeek`/`WriteSeek`). This WP also owns `parity/scenarios/formats/wav/` for B6.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-14` first and `cargo syrp wp check WP-2.1-14` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
