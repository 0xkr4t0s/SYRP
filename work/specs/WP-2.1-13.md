# WP-2.1-13: syrp-dsp-conv: Convolution with background IR loading, and Oversampling

## Purpose
Wave 2.1 item 13: `syrp-dsp-conv`, JUCE's `dsp::Convolution`, `dsp::ConvolutionMessageQueue` and `dsp::Oversampling`. Master plan §3 rates latency parity for both as high risk, so reported latency is a tested behaviour, not a detail. Convolution uses WP-2.1-10's FFT and the partitioned-convolution methods of the public DSP literature (uniformly partitioned overlap-save, and a non-uniform head/tail split); impulse-response preparation (resampling, trimming, normalising, partition transforms) runs off the audio thread and reaches it through `syrp_rt::RtHandoff`. Oversampling builds its stages from WP-2.1-11's half-band designs and resamples IRs with WP-2.1-16's windowed-sinc interpolator. This WP creates `syrp-dsp-conv`. Delivery: 3 PRs, each at most 1,200 changed lines (B1–B2, then B3, then B4–B6).

## Behaviour
- B1. Engine: `Convolution::new()` (uniformly partitioned, with the latency the `dsp::Convolution` documentation gives for the default), `Convolution::with_latency(Latency { samples })` and `Convolution::with_non_uniform(NonUniform { head_size })`, each implementing `DspProcessor<f32>` with `prepare`, `reset` and `process`, plus `latency()` returning exactly the delay the output has. Before any IR is loaded the processor passes input through delayed by `latency()`, as documented. Tests: for random IRs up to 2 s and random block-size sequences, the output equals direct time-domain convolution delayed by `latency()` within a relative RMS error of 1e-5; `latency()` matches the documented value for each mode.
- B2. Loading: `load_impulse_response(AudioBuffer<f32>, sample_rate, Stereo, Trim, Normalise)` with the meaning each of those enums has in the documentation; mono IRs feed both channels and stereo IRs map channel to channel. An IR at a different rate is resampled to the prepared rate (WP-2.1-16 `WindowedSinc`, `resample` profile). `Trim::Yes` removes leading and trailing samples below a threshold, and `Normalise::Yes` scales the IR to a target level; the documentation does not give either value, so choose them, pin each with a `b2_..._syrp_choice` test and list both under "Open questions" in the crate `AGENTS.md` for the harness. `current_ir_size()` reports the loaded length. Loading from files is not here: `syrp-formats` adds it over `AudioReader` later.
- B3. Background work: `ConvolutionMessageQueue::new(capacity)` owns one named worker thread (`std::thread`, joined on drop) that prepares IRs; several `Convolution`s may share one queue (`Convolution::with_queue(&queue)`), or each makes its own. A load called from any non-audio thread returns at once; when the queue is full the load is refused and `load_impulse_response` returns a coded error (continuing `errors/dsp.toml`), so the caller can retry; the engine keeps its current IR. The prepared engine reaches the audio thread through `RtHandoff`, the replaced one is dropped through `syrp_rt::DeferredDrop`, and the switch crossfades over a fixed length (Syrp's choice, documented) so it never clicks. `ConvolutionMessageQueue::manual()` makes a queue with no thread whose `process_pending()` runs the work, so tests are deterministic. A test loads IRs while `process` runs on another thread and checks that `process` never allocates (`syrp_rt::no_alloc`) and every output block is either the old or the new IR's result or the crossfade between them.
- B4. `Oversampling<S>::new(channels, factor_log2, FilterType, max_quality, use_integer_latency)` with `FilterType::HalfBandFirEquiripple` and `HalfBandPolyphaseIir` and the stage count, filter specifications and quality settings the `dsp::Oversampling` documentation gives; `init_processing(max_block)` (the only allocating call besides `new`), `reset`, `process_samples_up(AudioBlock) -> AudioBlockMut` (a view of the internal oversampled buffer), `process_samples_down(AudioBlockMut)`, `oversampling_factor()` and `latency_in_samples()`. With `use_integer_latency` a fractional `DelayLine` (WP-2.1-11, Thiran) pads the latency to the next whole sample, as documented. Tests (`resample` profile): passband ripple and stopband attenuation of each filter type and quality, a band-limited sine up then down returns delayed by exactly `latency_in_samples()`, and that latency equals the documented value for every factor from 1 to 4 and both filter types.
- B5. RT and determinism: `process`, `process_samples_up` and `process_samples_down` are allocation-free (`syrp_rt::no_alloc` tests); output is identical across block-size sequences (proptest), apart from the crossfade timing B3 documents. `benches/conv.rs` counts instructions (Callgrind, as in `crates/foundation/simd/benches/instructions.rs`) for a 1 s stereo IR at 48 kHz over 512-frame blocks in each mode. Errors continue `errors/dsp.toml`.
- B6. Add scenario files under `parity/scenarios/dsp/conv/` (the WP-0.1-11 format) in which JUCE runs `Convolution` in each mode and `Oversampling` at each factor and filter type on impulses, sines and noise, and reports latency; scenario files hold inputs only, and expected outputs come solely from harness runs. The crate `AGENTS.md` lists the ledger rows, thread affinity (who may load, who may process), and each `syrp_choice`.

## Not in this WP
Loading IRs from files or memory-mapped formats (`syrp-formats`), a GPU or multi-threaded convolution engine, and oversampling of non-power-of-two factors.

## Crate setup
Create `crates/audio/dsp-conv/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed. Dependencies: `syrp-dsp-core`, `syrp-dsp-filters`, `syrp-audio-basics`, `syrp-audio-api`, `syrp-simd`, `syrp-rt` and `syrp-error`. ## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-13` first and `cargo syrp wp check WP-2.1-13` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
