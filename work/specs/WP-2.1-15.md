# WP-2.1-15: syrp-format-flac: FLAC decoding (claxon) and encoding (flacenc) behind AudioFormat

## Purpose
Wave 2.1 item 15: `syrp-format-flac`, an `AudioFormat` implementation of the frozen `syrp-format-api` contract (WP-0.2-04) for FLAC, as JUCE's `FlacAudioFormat` documentation describes its support. Master plan §4.2 decides to wrap rather than build: `claxon` 0.4 (Apache-2.0, pure Rust) for decoding and `flacenc` 0.5 (Apache-2.0, pure Rust) for encoding, both behind this crate's own types so they can be replaced later. FLAC decoding is lossless, so §9.3 puts it in the `exact` profile. The container layout comes from the public FLAC format specification (RFC 9639) and Vorbis comment conventions only. This WP creates `syrp-format-flac`. Delivery: 2 PRs, each at most 1,200 changed lines (B1–B3, then B4–B6).

## Behaviour
- B1. `FlacAudioFormat` implements `AudioFormat`: `name()` and `file_extensions()` (`.flac`) as the `FlacAudioFormat` documentation lists them, `sample_rates()` and `bit_depths()` for writing (the rates and depths that documentation lists; 16 and 24-bit integer at least), and `can_read(header)` true for a stream starting with `fLaC`. Whether a leading ID3v2 tag is skipped is Syrp's choice (pin it with a `b1_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md`).
- B2. Reading through `claxon`: `spec()` and `length()` from `STREAMINFO` (an unknown total length of 0 is a coded error, Syrp's choice, listed); `read_samples` converts by dividing by 2^(bits − 1), the mapping WP-2.1-02 B2 states (implemented locally: format crates do not depend on `syrp-audio-basics`), for every bit depth from 4 to 32 that `claxon` decodes. Random access is correct for any start: forward reads never decode a frame twice, and a backward or far seek may restart decoding from the nearest earlier position the reader knows (the stream start, a `SEEKTABLE` point or a frame it has already passed); write the strategy and its cost in the rustdoc. Decoder errors map to coded errors continuing `errors/format.toml`, never a panic.
- B3. Metadata reading: `VORBIS_COMMENT` fields map to `Tag`s (`TITLE`, `ARTIST`, `ALBUM`, `GENRE`, `DATE`, `COMMENT` or `DESCRIPTION`, `TRACKNUMBER`, `COPYRIGHT`, `ENCODER`; field names compared case-insensitively, as the Vorbis comment convention says; others → `Tag::Custom` with the name as written); `CUESHEET` track indices → `CuePoint`s; `APPLICATION` and `PICTURE` blocks → `MetadataItem::Other(block name, bytes)`. Metadata is read in file order.
- B4. Writing through `flacenc`: integer input at the B1 depths, encoded frame by frame as samples arrive if `flacenc` 0.5 allows it, so memory stays bounded by one block; if it can only encode a whole source, buffer and say so, with the memory cost, in the crate `AGENTS.md` under "Known gaps". `WriterOptions::quality()` picks a compression level from a list the format documents (`None` gives the default). `finish` writes `STREAMINFO` with the total sample count and the MD5 of the decoded audio (patched by seeking back), and tags as a `VORBIS_COMMENT` block with the encoder's vendor string. Float input is rounded and clipped to the integer grid by the rule WP-2.1-02 B2 states.
- B5. Tests: every supported depth round-trips `f32 → FLAC → f32` exactly for values on its grid and the written file decodes with `claxon` to the same integers; metadata round-trips; seeks to random positions read the same samples as one long read (proptest); a byte-flip and truncation proptest over valid files never panics. Test streams are produced by the B4 writer or built from RFC 9639's layout, never copied from elsewhere. `cargo deny check` passes with both dependencies.
- B6. Add scenario files under `parity/scenarios/formats/flac/` (the WP-0.1-11 format) in which JUCE reads the B5 files and writes FLAC at each documented depth and quality; scenario files hold inputs only, and expected outputs come solely from harness runs. Compare decoded samples (`exact`) rather than encoded bytes, because the two encoders may choose different frames. The crate `AGENTS.md` lists the ledger row, both dependencies and their licences, and each `syrp_choice`.

## Not in this WP
Ogg-encapsulated FLAC, the format manager (`syrp-formats`) and memory-mapped readers.

## Crate setup
Create `crates/audio/format-flac/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed. Dependencies: `syrp-format-api`, `syrp-audio-api`, `syrp-error`, `claxon` 0.4 and `flacenc` 0.5 (explicit versions in this crate's `Cargo.toml`; list both in `deps_added`). ## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-15` first and `cargo syrp wp check WP-2.1-15` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
