# WP-2.1-17: syrp-format-aiff: AIFF and AIFF-C reading and writing with marker, instrument and text metadata

## Purpose
Wave 2.1 item 14 (the AIFF half; WAV is WP-2.1-14), numbered after the Wave 2.1 list because the item holds two crates. `syrp-format-aiff` implements the frozen `syrp-format-api` contract (WP-0.2-04) for AIFF and AIFF-C, as JUCE's `AiffAudioFormat` documentation describes the format's support. Master plan §4.2 decides to build AIFF rather than wrap a crate, and §9.3 puts integer PCM decoding in the `exact` profile. The layout comes from Apple's public *Audio Interchange File Format* 1.3 and AIFF-C specifications only. It shares nothing with WP-2.1-14, so both run in parallel. This WP creates `syrp-format-aiff`. Delivery: 2 PRs, each at most 1,200 changed lines (B1–B3, then B4–B6).

## Behaviour
- B1. `AiffAudioFormat` implements `AudioFormat`: `name()` and `file_extensions()` (`.aiff`, `.aif`, `.aifc`) as the `AiffAudioFormat` documentation lists them, `sample_rates()` and `bit_depths()` for writing (8, 16, 24 and 32 integer, and 32-bit float), and `can_read(header)` true for a `FORM` chunk of type `AIFF` or `AIFC`.
- B2. Reading: walk the `FORM` chunks big-endian (with the pad byte after odd-sized chunks, skipping unknown chunks); `COMM` gives channels, frame count, bits and the sample rate as an 80-bit IEEE 754 extended value, which a `extended_to_f64` helper converts exactly for every rate representable in `f64` (tested against hand-built values, including 44,100 and 48,000, denormals and zero); `SSND` honours its offset and block size. AIFF-C compression types `NONE` (big-endian integer), `sowt` (little-endian integer), `fl32` and `fl64` (big-endian float, either case) are read; any other compression is a coded error naming the four-character code. Integers convert to floats by dividing by 2^(bits − 1), the mapping WP-2.1-02 B2 states (implemented locally: format crates do not depend on `syrp-audio-basics`) (AIFF 8-bit is signed). Every size and count is checked against the remaining input before allocating; malformed input is a coded error continuing `errors/format.toml`, never a panic. Where the specifications leave a case open (an `SSND` that runs past the end, a `COMM` frame count that disagrees with `SSND`), choose, pin it with a `b2_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md` for the harness.
- B3. Metadata reading, into the contract's `Metadata` in file order: `MARK` markers → `CuePoint`s (id, position, Pascal-string name as label); `INST` sustain and release loops → `SampleLoop`s whose start and end are the referenced markers' positions (play mode forward or forward/backward; "no looping" adds nothing), and the base note, detune, key and velocity ranges and gain → `Other("INST", bytes)` unchanged; `NAME` → Title, `AUTH` → Artist, `(c) ` → Copyright, `ANNO` → Comment (several `ANNO` chunks keep their order as several items); `COMT`, `APPL`, `ID3 ` and every other chunk → `MetadataItem::Other(chunk_id, bytes)`.
- B4. Writing: plain AIFF for integer PCM at 8, 16, 24 and 32 bits, and AIFF-C with `fl32` for 32-bit float (with the `FVER` chunk the AIFF-C specification requires); the sample rate written as an exact 80-bit extended value. Float input to an integer format follows the rounding, clipping and NaN rule WP-2.1-02 B2 states. Sizes are patched in `finish`. Cue points and loops are written as `MARK` and `INST` (loops that do not fit `INST`'s two loops, or whose kind it cannot express, are dropped, Syrp's choice pinned with a `b4_..._syrp_choice` test; `AiffAudioFormat::unwritable_items(&Metadata)` returns the items that would be dropped, so a caller can check first), text tags as `NAME`/`AUTH`/`(c) `/`ANNO`, and `Other` items byte for byte, before `SSND`.
- B5. Tests: every format round-trips `f32 → file → f32` exactly for values on its grid; markers, loops and text round-trip; `sowt`, `fl64`, odd chunk sizes, non-zero `SSND` offsets and unknown chunks read correctly; a byte-flip and truncation proptest over valid files never panics and never allocates more than the input justifies. Test files are built by the tests from the public layouts, never copied from elsewhere.
- B6. Add scenario files under `parity/scenarios/formats/aiff/` (the WP-0.1-11 format) in which JUCE reads the B5 files (including malformed ones) and writes each format with markers and loops; scenario files hold inputs only, and expected outputs come solely from harness runs. The crate `AGENTS.md` lists the ledger row, the mapping from JUCE's documented metadata keys to the contract's items, and each `syrp_choice`.

## Not in this WP
Compressed AIFF-C codecs (`ima4`, `ulaw`, `alaw` and the like), the format manager (`syrp-formats`), and memory-mapped readers.

## Crate setup
Create `crates/audio/format-aiff/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed. Dependencies: `syrp-format-api`, `syrp-audio-api` and `syrp-error`. This WP also owns `parity/scenarios/formats/aiff/` for B6.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-17` first and `cargo syrp wp check WP-2.1-17` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
