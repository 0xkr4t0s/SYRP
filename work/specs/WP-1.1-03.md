# WP-1.1-03: syrp-io: InputStream and OutputStream, MemoryBlock, memory, buffered and subregion streams

## Purpose
The stream layer of `syrp-io` from master plan §5.2 (L2 Core) and Wave 1.1 item 3. Files (WP-1.1-04), zip and gzip (WP-1.1-05), `WebInputStream` (WP-1.1-09), the format readers and `syrp-state` persistence all read and write through these traits. This is cold-path code (ADR 0003 D2): ordinary idiomatic Rust, no data-oriented layout. Delivery: 2 PRs (B1–B3, then B4–B7).

## Behaviour
- B1. `InputStream`: a trait with `std::io::Read` as a supertrait, adding `total_length() -> Option<u64>` (`None` when unknown), `position()`, `set_position(u64) -> Result<(), IoError>`, `is_exhausted()`, `skip_next_bytes(n)`, `read_entire_stream_as_string()` (UTF-8, or UTF-16 when the text starts with a byte-order mark; a UTF-8 BOM is dropped) and `read_into_memory_block(&mut MemoryBlock, max_bytes: Option<u64>)`. Provided methods read `u8`, `bool`, `i16`, `i32`, `i64`, `f32` and `f64` in little- and big-endian forms, `read_compressed_int`, `read_string` (UTF-8 up to a NUL) and `read_next_line` (strips `\n` or `\r\n`). Fixed-size reads that hit the end return `SYRP-IO-0001` instead of JUCE's zero (a documented deviation). Every `Read` implementation that can seek gets these through a blanket adapter (`StdInputStream<R: Read + Seek>`).
- B2. `OutputStream`: a trait with `std::io::Write` as a supertrait, adding `position()`, `set_position(u64) -> Result<(), IoError>`, typed little- and big-endian writers matching B1, `write_compressed_int`, `write_string` (UTF-8 plus NUL), `write_text(text, as_utf16, write_bom, line_ending: Option<&str>)`, `write_repeated_byte`, `write_from_input_stream(&mut dyn InputStream, max_bytes: Option<u64>) -> u64` and a per-stream new-line string. Proptest: for every typed writer, writing a random value and reading it back with the matching B1 reader gives the same value (floats bit-exact, NaN included). The compressed-int byte layout follows the `OutputStream::writeCompressedInt` documentation; where the documentation leaves the layout open, choose one, document it and list it under "Open questions" in the crate `AGENTS.md` for the differential harness (WP-0.1-11), because JUCE's binary `ValueTree` format depends on it.
- B3. `MemoryBlock`: an owned, growable byte block with no public fields: `new`, `with_size(n, zeroed)`, `from_slice`, `len`, `is_empty`, `set_size(n, zero_new_bytes)`, `ensure_size`, `fill(byte)`, `append`, `insert(offset, bytes)`, `remove_section(start, len)`, `replace_all`, `copy_from(src, dest_offset)` and `copy_to(dest, src_offset)` (out-of-range parts are clipped, never panic, as the class documentation describes), `bit_range(bit_start, num_bits)` and `set_bit_range`, `swap_with`, `Deref<Target = [u8]>`, `DerefMut`, `PartialEq`, `Hash` and `to_string_lossy`. Proptest: random sequences of these operations agree with a plain `Vec<u8>` model, with negative and past-the-end offsets included. `toBase64Encoding`/`fromBase64Encoding` are out of scope (their format is JUCE-specific; `syrp-strings` has standard Base64).
- B4. `MemoryInputStream` over a borrowed `&[u8]` or an owned `MemoryBlock`/`Vec<u8>` (JUCE's "keep internal copy"), seekable, `total_length` known. `MemoryOutputStream` writing into its own growing `MemoryBlock`, into a caller's `&mut MemoryBlock` (appending at the current size), or into a fixed `&mut [u8]` (a write past its end writes nothing and returns `SYRP-IO-0002`); `data()`, `len()`, `reset()`, `preallocate(n)`, `to_utf8_string()` and `into_memory_block()`. Setting the position past the end of written data is either an error or zero-fill: choose, document and pin it with a `b4_..._syrp_choice` test.
- B5. `BufferedInputStream<S: InputStream>` with a configurable buffer size and `peek_byte()`; seeking inside the buffered range does not re-read the source (tested with a counting source). `SubregionStream<S>` exposes the window `[start, start + length)` of a source with positions relative to `start` and the length clipped to the source. Both own their source (`Box<dyn InputStream>` works too) and give it back with `into_inner()`.
- B6. `InputSource`: a trait with `create_input_stream() -> Result<Box<dyn InputStream + Send>, IoError>`, `create_input_stream_for(relative_path: &str)` and `hash_code() -> u64`. Implementations for files and URLs are in WP-1.1-04 and WP-1.1-09.
- B7. Errors use the new `errors/io.toml` domain (`SYRP-IO-0001`...); an `IoError` keeps the underlying `std::io::Error` as its source and converts into `std::io::Error` so the traits compose with `std` code. No platform code and no third-party dependencies: the crate passes `cargo miri test` (master plan §9.8).

## Not in this WP
`File` and file streams (WP-1.1-04), zip and gzip (WP-1.1-05), MIME types, `FileLogger`, JUCE's binary `var` stream format.

## Crate setup
Create `crates/core/io/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L2"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.1-03` first and `cargo syrp wp check WP-1.1-03` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
