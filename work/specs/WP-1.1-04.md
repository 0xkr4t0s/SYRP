# WP-1.1-04: syrp-io: File, file streams, special locations, directory iteration, TemporaryFile and MemoryMappedFile

## Purpose
The file-system layer of `syrp-io` from master plan §5.2 (L2 Core) and Wave 1.1 item 4. Everything that loads or saves user data goes through `File`: audio formats, `PropertiesFile`, the plugin scanner and the file browser. It builds on the WP-1.1-03 stream traits and uses `syrp_sys::Time` (WP-1.1-12) for file times. Delivery: 3 PRs (B1–B3, then B4–B6, then B7–B8).

## Behaviour
- B1. `File`: an absolute path value that wraps a `PathBuf` (`AsRef<Path>`, `From<File> for PathBuf`, `File::new(abs) -> Result<File, IoError>`, which rejects relative paths, and `File::from_cwd_relative`). Pure path functions, as the `File` documentation describes them: `full_path_name`, `file_name`, `file_extension` (with the leading dot), `file_name_without_extension`, `parent_directory`, `child_file(rel)` (resolves `.` and `..` lexically), `sibling_file`, `with_file_extension`, `is_a_child_of`, `relative_path_from(dir)`, `nonexistent_child_file(prefix, suffix, numbers_in_brackets)`, `create_legal_file_name`, `create_legal_path_name` and `are_file_names_case_sensitive()`. Equality and ordering follow the platform: case-insensitive on Windows and macOS, case-sensitive on Linux. Test with per-platform vector tables.
- B2. File-system operations, each returning `Result`: `exists`, `exists_as_file`, `is_directory`, `size`, `last_modification_time`/`set_last_modification_time`, `last_access_time`, `creation_time` (as `syrp_sys::Time`), `has_write_access`, `is_symbolic_link`, `linked_target`, `create_directory` (with parents), `create` (an empty file, with parents), `delete_file`, `delete_recursively(follow_symlinks)`, `move_file_to`, `copy_file_to`, `copy_directory_to`, `replace_with_file`, `load_file_as_string`, `load_file_as_data`, `replace_with_text`, `replace_with_data`, `append_text`, `append_data`, `read_lines`, `has_identical_content_to`, `bytes_free_on_volume`, `volume_total_size` and `move_to_trash`. Tests run only inside a fresh temporary directory.
- B3. `FileInputStream` and `FileOutputStream` implement the WP-1.1-03 traits. As the class documentation says, `FileOutputStream` appends to an existing file; `truncate()` and `set_position(0)` overwrite it. Open failures are `Result` errors, not a `failedToOpen()` flag. `FileInputSource` implements `InputSource`.
- B4. Special locations: `File::special_location(SpecialLocation) -> Result<File, IoError>` for user home, documents, desktop, music, movies, pictures and application data; common application data and common documents; temporary directory; current executable, current application (the bundle on macOS), invoked executable and host application; and global applications. Also `current_working_directory` and `set_as_current_working_directory`. Write the per-platform table into the rustdoc: Linux uses the XDG base directories and `user-dirs.dirs` with documented fallbacks; macOS uses the `~/Library` and `/Library` folders; Windows uses Known Folders (`SHGetKnownFolderPath`). Tests check that every location is absolute, that the temp directory is writable, and that home matches `HOME` or `USERPROFILE`.
- B5. Directory iteration: `RangedDirectoryIterator::new(dir, recursive, wildcard, FileKinds { files, directories, hidden })` yields `DirectoryEntry` values (file, is-directory, is-hidden, size, modification and creation time, read-only) plus an `estimated_progress()`. The wildcard is a `;`-separated list such as `*.wav;*.aif?` matched against the file name (`*` and `?`), case-insensitively where file names are. Recursion does not follow directory symlinks unless asked, and never loops on a symlink cycle. Order is unspecified, so tests sort. Also `File::find_child_files`, `number_of_child_files`, the `FileFilter` trait, `WildcardFileFilter` (file patterns, directory patterns, description) and `FileSearchPath` (parse and format the `;`-separated form, `add`, `remove`, `remove_redundant_paths`, `remove_nonexistent_paths`, `find_child_files`, `is_file_in_path`). Proptest the wildcard matcher against a small recursive reference matcher.
- B6. `TemporaryFile`: a temporary sibling (or a file in the temp directory) with a random suffix; `overwrite_target_file_with_temporary()` replaces the target with an atomic rename where the platform allows, and on Windows retries a bounded number of times on a sharing violation. The temporary file is deleted on drop. Options for a hidden name and numbers in brackets, as documented.
- B7. `MemoryMappedFile`: `open(file, Mode::{ReadOnly, ReadWrite}, range: Option<Range<u64>>, exclusive)`, `data() -> &[u8]`, `data_mut()` (read-write only) and `range()`. The OS mapping is page-aligned around the requested range, and `data()` is exactly the requested range clipped to the file. Opening is `unsafe` (another process can change or truncate the file under the mapping); say so in a `# Safety` section. `memmap2` may be used, or `libc`/`windows-sys` directly with a `// SAFETY:` comment on every block. Tests: mapped bytes equal the bytes `FileInputStream` reads; a read-write change persists after drop; a range past the end is clipped; a zero-length file maps to an empty slice without an error.
- B8. Errors continue `errors/io.toml`. OS failures carry the raw `errno` or `GetLastError` value and the path in the message.

## Platforms
Linux, macOS and Windows are all required, and PR CI must pass on all three (ubuntu-24.04 x64, macos-15 arm64, windows-2025 x64). Per platform:
- Linux: XDG locations; `move_to_trash` follows the freedesktop.org Trash specification under `$XDG_DATA_HOME/Trash`, and returns the coded "unsupported" error when the trash would be on another volume; `mmap` through `libc` or `memmap2`.
- macOS: `~/Library` locations; `move_to_trash` uses `NSFileManager trashItemAtURL` (through `objc2-foundation`); case-insensitive comparison by default (APFS case-sensitive volumes are a documented gap).
- Windows: Known Folders; `move_to_trash` uses `IFileOperation` or `SHFileOperationW` with undo allowed; `CreateFileMappingW` and `MapViewOfFile`; paths longer than `MAX_PATH` work (use `\\?\` internally where needed).
Other targets compile, and their platform functions return a documented "unsupported" error.

## Not in this WP
`DirectoryIterator` (deprecated in JUCE, superseded by `RangedDirectoryIterator`), Android documents (`AndroidDocument*`), iOS bundle locations, file-change notification, `FileLogger`.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-1.1-04` first and `cargo syrp wp check WP-1.1-04` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
