# WP-2.1-12: syrp-dsp-fx: gain, bias, panner, oscillator, waveshaper, dry/wet, dynamics, chorus, phaser and reverb

## Purpose
Wave 2.1 item 12: `syrp-dsp-fx`, the effect processors of `juce_dsp`, built on WP-2.1-10's `DspProcessor` model and WP-2.1-11's filters, `BallisticsFilter` and `DelayLine`, and lane-generic over `syrp_simd::Sample` wherever the state is per channel (ADR 0003 D5). `dsp::Reverb` wraps WP-2.1-16's `Reverb`, so this WP also waits for that. Tolerances come from master plan §9.3: `f32-arith` for gain, bias and panning, `nonlinear` for the oscillator, waveshaper and dynamics, and `algorithmic` for chorus, phaser and reverb (behavioural equivalence, not sample parity). This WP creates `syrp-dsp-fx`. Delivery: 3 PRs, each at most 1,200 changed lines (B1–B3, then B4, then B5–B6).

## Behaviour
- B1. Level and placement: `Gain<S>` (`set_gain_linear`, `set_gain_decibels`, `gain_linear`, `gain_decibels`, `set_ramp_duration_seconds`, `is_smoothing`), `Bias<S>` (`set_bias`, `bias`, `set_ramp_duration_seconds`) and `Panner<S>` (`set_rule`, `set_pan` over −1..1). Changes ramp linearly over the ramp duration, built on `syrp_audio_basics::control::SmoothedValue`; a zero duration jumps. `PannerRule` has one variant per rule the `dsp::Panner` documentation lists; write each rule's left and right gain law in its rustdoc and test it at pan −1, 0 and +1 and at a mid point. A `Panner` takes a stereo or mono-to-stereo block, as documented.
- B2. `Oscillator<S>`: built from a function over one cycle (`−π..π`) and an optional table size (when given, the function is sampled into a WP-2.1-10 `LookupTableTransform`), with `set_frequency(hz, force)`, `frequency`, `process_sample(input)` (the input argument has the meaning the `dsp::Oscillator` documentation gives it; pin that with a test, and if the documentation leaves it open, choose and list it under "Open questions"), `process(ctx)` and `reset`. Frequency changes ramp as in B1 unless `force` is set. Tests: a sine oscillator matches `sin` at the expected phase (`nonlinear` static error), a frequency step keeps phase continuous, and a table-backed oscillator stays within the table's measured error.
- B3. `WaveShaper<S, F>` (a stored shaping function applied per sample; `process` with no state) and `DryWetMixer<S>`: `new(maximum_wet_latency_samples)`, `set_mixing_rule`, `set_wet_mix_proportion(0..1)`, `set_wet_latency(samples)`, `push_dry_samples(block)` and `mix_wet_samples(block)`, as the `dsp::DryWetMixer` documentation describes. The dry path is delayed by the wet latency through a WP-2.1-11 `DelayLine`, so a wet path with a known latency lines up exactly; one variant per mixing rule the documentation lists, each law written in its rustdoc and tested at mix 0, 0.5 and 1.
- B4. Dynamics: `Compressor<S>` (`set_threshold` in dB, `set_ratio` ≥ 1, `set_attack` and `set_release` in ms), `Limiter<S>` (`set_threshold`, `set_release`) and `NoiseGate<S>` (`set_threshold`, `set_ratio`, `set_attack`, `set_release`), each detecting level with a `BallisticsFilter` in the mode the documentation names (peak for the compressor and limiter, RMS for the gate). Tests (`nonlinear` profile): the static gain curve of each against its closed form from 20 dB below to 20 dB above the threshold, and attack and release times measured on a level step within ±1% of the setting. Where the documentation does not fix a detail that changes the output (knee shape, the limiter's internal stages, its output ceiling), choose, pin it with a `b4_..._syrp_choice` test and list it under "Open questions" in the crate `AGENTS.md` for the harness.
- B5. Modulation and space: `Chorus<S>` (`set_rate` in Hz, `set_depth` 0..1, `set_centre_delay` in ms, `set_feedback` −1..1, `set_mix` 0..1) and `Phaser<S>` (`set_rate`, `set_depth`, `set_centre_frequency`, `set_feedback`, `set_mix`) with the parameter ranges the documentation gives, built from a low-frequency oscillator, `DelayLine` (chorus) and a cascade of first-order all-pass stages (phaser, stage count Syrp's choice if undocumented, written in the rustdoc); `Reverb` wrapping `syrp_audio_basics::Reverb` with `set_parameters`, `set_enabled`, `is_enabled` and the documented mono and stereo handling. Tests use the `algorithmic` checks: stereo correlation, spectral envelope per third-octave band of white noise through the effect at fixed settings, and, for the reverb, RT60 against the value WP-2.1-16 measured.
- B6. Every processor implements `DspProcessor`; `process` and every per-sample call are allocation-free (`syrp_rt::no_alloc` tests); the lane-pack path of each lane-generic processor equals its scalar path within `f32-arith` for random parameters and input (ADR 0003 D7); a setter given a value outside its documented range clamps, and a test pins that. `benches/fx.rs` counts instructions (Callgrind, as in `crates/foundation/simd/benches/instructions.rs`) for `Compressor<f32>` versus `Compressor<F32x8>` and for `Chorus<f32>` over 512 frames. Errors, if any, continue `errors/dsp.toml`. The crate `AGENTS.md` lists the ledger rows, which processors are lane-generic, and each `syrp_choice`.

## Not in this WP
Convolution and oversampling (WP-2.1-13), band-limited oscillator variants (a later WP), the `syrp-dsp` umbrella crate, and `juce_audio_basics`' `Reverb` itself (WP-2.1-16).

## Crate setup
Create `crates/audio/dsp-fx/` with `Cargo.toml` (inherit `version`, `edition`, `rust-version`, `repository`, `authors`, `publish` from the workspace; `[lints] workspace = true`), `[package.metadata.syrp] layer = "L3"`, an `AGENTS.md` following `docs/agents/crate-agents-template.md`, and `src/lib.rs`. Workspace members are globbed, so no root edit is needed. Dependencies: `syrp-dsp-core`, `syrp-dsp-filters`, `syrp-audio-basics`, `syrp-audio-api`, `syrp-simd`, `syrp-rt` and `syrp-error`.

## Rules that apply to every WP
- Clean room: work only from this spec, the master plan (`docs/design/master-plan.md`) and public JUCE *documentation* for behaviour. Never fetch or recall JUCE source code.
- Name every test after the behaviour it proves, prefixed with its id, for example `b3_try_push_fails_when_full`.
- Run `cargo syrp wp show WP-2.1-12` first and `cargo syrp wp check WP-2.1-12` last. A PR is ready only when that command exits 0.
- Shared files (workspace `Cargo.toml`, CI, `deny.toml`) are not yours. If you need a new third-party dependency in `[workspace.dependencies]`, declare it with an explicit version in your crate's own `Cargo.toml` and list it in the PR front matter `deps_added`; the adversarial verifier reviews it.
